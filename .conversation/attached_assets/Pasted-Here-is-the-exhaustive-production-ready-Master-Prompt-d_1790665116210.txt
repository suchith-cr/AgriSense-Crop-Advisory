# MASTER PROMPT: AI-Powered Agriculture Crop Advisory Assistant

### 1. Header & System Persona Role

**Role:** You are an Elite Principal Full-Stack Engineer, AI Systems Architect, and UI/UX Expert.
**Task:** Build an end-to-end, production-ready "AI-Powered Agriculture Crop Advisory Assistant." You will generate all necessary frontend and backend code, database schemas, and AI integration logic without skipping steps or leaving placeholders. Write clean, modular, highly scalable, and well-commented code.

### 2. Core Mission Directive

Create a comprehensive, intelligent web application that solves critical challenges for farmers. The system must seamlessly accept inputs (crop images, location data, and crop details), orchestrate data with backend APIs, leverage Google's latest Gemini AI models for multi-modal analysis, and securely store user histories in a PostgreSQL database. The application must be instantly usable, responsive, and robust against errors.

### 3. Product Goal

To provide farmers with a unified, AI-driven dashboard that mitigates agricultural risks by:

1. Detecting crop diseases from uploaded images with high accuracy.
2. Providing actionable, weather-based farming alerts.
3. Suggesting optimal selling times and market strategies to maximize farmer income.

### 4. Mandatory Features

* **Disease Detection Engine:** Drag-and-drop image upload to analyze leaf/crop anomalies using Gemini's multi-modal capabilities.
* **Weather Advisory Module:** Location-based input that generates AI-interpreted risk alerts (e.g., impending frost, drought, heavy rainfall).
* **Market Intelligence Tracker:** Crop-specific yield analysis that predicts optimal market timing based on historical logic and AI reasoning.
* **Unified Farmer Dashboard:** A central hub where users can view all past AI assessments and historical data.

### 5. Technology Requirements

You MUST strictly adhere to the following tech stack:

* **Frontend:** React.js (Functional components, Hooks), Tailwind CSS (for all styling).
* **Backend:** Node.js with Express.js.
* **Database:** Replit Postgres (PostgreSQL).
* **AI Integration:** `@google/genai` SDK (Strictly server-side; NEVER expose API keys on the frontend).
* **Validation:** Zod (for validating all API requests and AI structured JSON outputs).

### 6. Application Pages (Routes)

Implement the following React Router (`react-router-dom`) paths:

* `/` - **Dashboard:** Overview of recent analyses and quick links to modules.
* `/disease-scanner` - **Scanner:** UI for uploading crop images and viewing diagnostic results.
* `/weather-alerts` - **Weather:** Form for location input and display of meteorological advisories.
* `/market-insights` - **Market:** Input for crop type/volume and display of market timing suggestions.

### 7. User Flow

1. **Entry:** User lands on the Dashboard.
2. **Action Selection:** User selects one of the three primary modules (Disease, Weather, Market).
3. **Data Input:** User provides necessary context (Image upload, location text, or crop details).
4. **Processing state:** UI shows a loading skeleton/spinner with helpful farming tips.
5. **AI Execution:** Frontend sends data to Node/Express backend -> Backend validates with Zod -> Backend calls `@google/genai` -> AI returns structured JSON -> Backend saves to Replit Postgres -> Backend responds to Frontend.
6. **Result:** User views the formatted AI advisory and can navigate back to the Dashboard to see it in their history.

### 8. Target Domains & Categorization

* **Primary Domain:** Agronomy, Plant Pathology, Agricultural Economics.
* **Tone:** Professional, accessible, practical, and highly empathetic to the realities of farming.
* **Units:** Ensure metrics are practical (e.g., percentage confidence for diseases, actionable timeframes for markets).

### 9. Form & Advisory Configuration

* **Disease Form:** File input (accepts `.jpg`, `.png`, max 5MB) with drag-and-drop zone.
* **Weather Form:** Text input for `Location (City/Region)` and dropdown for `Current Season`.
* **Market Form:** Dropdown for `Crop Type` (e.g., Wheat, Corn, Rice, Soybeans) and number input for `Estimated Yield (Tons)`.
* **Advisory UI:** Results must be displayed in clean, Tailwind-styled cards with color-coded severity badges (Red=Critical, Yellow=Warning, Green=Optimal).

### 10. Database Schema (Production SQL for PostgreSQL)

Execute this schema in Replit Postgres to initialize the database:

```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    farmer_name VARCHAR(255) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE crop_diagnostics (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    image_url TEXT,
    disease_name VARCHAR(255),
    confidence_score NUMERIC(5,2),
    treatment_plan TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE weather_advisories (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    location VARCHAR(255),
    alert_level VARCHAR(50),
    action_plan TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE market_insights (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    crop_type VARCHAR(100),
    best_time_to_sell VARCHAR(100),
    market_strategy TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

```

### 11. Row Level Security (RLS) / Data Isolation Rules

Though a full authentication system is out of scope for this hackathon build, architect the queries to always filter by a simulated `user_id` passed in the headers or body.

* Ensure `SELECT`, `INSERT`, and `UPDATE` operations on `crop_diagnostics`, `weather_advisories`, and `market_insights` strictly enforce `WHERE user_id = $1`.

### 12. Backend API Routes

Implement these endpoints in Express.js:

* `GET /api/dashboard/:userId` - Fetches the 5 most recent entries from all three tables.
* `POST /api/analyze-disease` - Accepts Base64 image and `userId`.
* `POST /api/weather-advisory` - Accepts `location`, `season`, and `userId`.
* `POST /api/market-timing` - Accepts `cropType`, `yield`, and `userId`.
